## Summary

Ripley analyzed CI/CD deployment strategies across both repos:

**Key Finding:** teamskills uses GitHub Environments (`production` + `staging`) for deployment gating and visibility. azure-idp-workshop has no Environments defined.

**Architectural Difference:**
- **teamskills**: Dedicated staging resource group (`rg-teamskills-staging`); stable URLs across all PRs; manual approval gate on production
- **azure-idp-workshop**: Container Apps multi-revision mode per PR (ephemeral, per-PR URLs); no approval gates

**Recommendation:** Add `environment: production` to `.github/workflows/deploy-prod.yml` for Phase 1. Do NOT use Environments for PR staging (they're meant for persistent targets, not ephemeral revisions).

**Benefits:**
- Production deployments visible in GitHub Deployments sidebar
- Optional approval rules in repo settings
- Scoped environment secrets capability (future)
- No workflow logic changes, no cost impact

**Implementation:** 1-line change. Includes optional Phase 2 guidance if Eric wants separate staging RG (like teamskills).
