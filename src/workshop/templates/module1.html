Module 1: Structured Extraction — When DI Wins

DI excels at forms with predefined fields and predictable variations. Compare extraction quality, confidence scoring, and cost - DI is faster, cheaper ($0.01/page vs $0.05/page CU custom), and deterministic.

🔬 What Are We Comparing?

🔵 Document Intelligence (DI)

Microsoft's battle-tested OCR + layout engine. Deterministic results, fast, cheap ($0.01/page). Built for high-volume, structured document processing - invoices, receipts, onboarding packets, and other fixed forms.

🟣 Content Understanding (CU)

Azure's newer multimodal service. Also does layout extraction, but CU is built for understanding — GenAI-powered analysis. Layout mode here is CU's simplest capability.

🏭 When to Use This in Production

  • Invoice processing pipelines — DI's prebuilt-invoice extracts fields + line items automatically
  • Receipt scanning — DI's prebuilt-receipt handles photos of receipts with high accuracy
  • Form digitization — DI excels at forms with fixed fields, even when labels drift between versions (tax forms, onboarding packets, applications)
  • High-volume OCR — DI processes thousands of pages/minute at $0.01/page with deterministic results

🔬 Try It Yourself

# pip install azure-ai-documentintelligence azure-ai-contentunderstanding azure-identity
from azure.ai.documentintelligence import DocumentIntelligenceClient
from azure.ai.documentintelligence.models import AnalyzeDocumentRequest
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.identity import DefaultAzureCredential

endpoint = "https://<your-resource>.cognitiveservices.azure.com"
credential = DefaultAzureCredential()

# --- Document Intelligence (Layout) ---
di_client = DocumentIntelligenceClient(endpoint, credential)
with open("invoice.pdf", "rb") as f:
    poller = di_client.begin_analyze_document("prebuilt-layout", AnalyzeDocumentRequest(bytes_source=f.read()))
di_result = poller.result()
print(f"DI found {len(di_result.pages)} pages, {len(di_result.tables or [])} tables")

# --- Content Understanding (Layout) ---
cu_client = ContentUnderstandingClient(endpoint, credential)
with open("invoice.pdf", "rb") as f:
    poller = cu_client.begin_analyze("prebuilt-layout", body=f.read(), content_type="application/octet-stream")
cu_result = poller.result()
print(f"CU returned {len(cu_result.get('contents', []))} content segments")
# Get an access token (requires az login)
TOKEN=$(az account get-access-token --resource https://cognitiveservices.azure.com --query accessToken -o tsv)
ENDPOINT="https://<your-resource>.cognitiveservices.azure.com"

# --- Document Intelligence (Layout) ---
# Start analysis
DI_URL=$(curl -s -D - -X POST "$ENDPOINT/formrecognizer/documentModels/prebuilt-layout:analyze?api-version=2024-11-30" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/pdf" \
  --data-binary @invoice.pdf | grep -i operation-location | tr -d '\r' | cut -d' ' -f2)
# Poll for result
curl -s -H "Authorization: Bearer $TOKEN" "$DI_URL" | python -m json.tool

# --- Content Understanding (Layout) ---
CU_URL=$(curl -s -D - -X POST "$ENDPOINT/contentunderstanding/analyzers/prebuilt-layout:analyze?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/pdf" \
  --data-binary @invoice.pdf | grep -i operation-location | tr -d '\r' | cut -d' ' -f2)
curl -s -H "Authorization: Bearer $TOKEN" "$CU_URL" | python -m json.tool

      'Microsoft.Authorization/roleDefinitions',

📄 Choose a Document

🎯 What to Look For

  • Speed — Watch the progress indicators. DI is typically faster on structured documents.
  • Tables — DI excels at detecting and structuring table data with row/column awareness.
  • Prebuilt fields — DI's prebuilt models extract specific fields (merchant, total, date) with confidence scores — no GenAI needed.
  • Variation handling — Compare Purchase Order A/B or Vendor Intake A/B. The labels change, but the business entities stay the same.
  • Content format — DI returns raw text + structure. CU returns markdown-formatted content.
  • API trace — Expand the trace to see exact request/response details and timing.

🔍 Side-by-Side Comparison Guide

⏱️ Response Time

Check the millisecond timings. DI is typically 2-5× faster on structured docs because it uses deterministic extraction — no GenAI inference overhead.

📊 Table Detection

DI detects tables with explicit row/column structure. CU returns markdown tables. Toggle "Raw JSON" to see the structural difference.

🎯 Prebuilt Fields

Scroll down to the green section. DI either extracts typed prebuilt fields or shows you the layout fallback path you would normalize for predictable form variants.

📄 Content Format

DI returns plain text with bounding boxes. CU returns markdown with headers and formatting. Both are valid — different trade-offs.

💡 What to Notice — DI Wins Here

  • DI is built for structured, high-volume extraction. Prebuilt models extract receipt/invoice fields without any configuration.
  • DI provides deterministic results — same input always yields the same output. No GenAI variability.
  • DI is faster and cheaper — $0.01/page vs $0.05/page for CU custom extraction.
  • Confidence scoring — each extracted field has a confidence percentage. Green (≥90%) means high certainty. This enables automated processing rules.
  • Controlled layout drift is still a DI problem. For Purchase Order A/B and Vendor Intake A/B, DI layout plus a thin normalization layer is often enough.
  • Compare the API traces — notice DI's speed advantage on structured documents.
  • Prebuilt model catalog: receipt, invoice, W-2, ID document, health insurance card, business card, and more — all out of the box.
