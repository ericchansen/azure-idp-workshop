🏗️ Architecture & Setup — PTU + SimpleL7Proxy

⚡ What is PTU (Provisioned Throughput)?

PAYG (Pay-As-You-Go) — you pay per token/call. Simple, but costs scale linearly and you're subject to rate limits.

PTU (Provisioned Throughput Units) — you reserve dedicated capacity. Fixed monthly cost regardless of usage. No rate limits within your allocation, so headroom outside peak traffic can still be used for background work.

When PTU makes sense: When your monthly PAYG spend exceeds the PTU reservation cost, when you need guaranteed throughput for batch processing without throttling, or when you already carry PTU for peak hours and can use that off-hours capacity for jobs like document enrichment instead of leaving it idle.

🔄 SimpleL7Proxy — How It Works

SimpleL7Proxy is an open-source Layer 7 router for Azure AI workloads:

  • Priority routing — PTU first, PAYG fallback when PTU is saturated
  • Circuit breaker — auto-failover when a backend returns errors (configurable threshold)
  • Health probes — continuous backend monitoring with configurable intervals
  • Managed Identity — no API keys in config, uses Azure RBAC
  • Self-hosted — runs as a Container App, full control over routing logic

🧱 Deploy SimpleL7Proxy

Deploy as a Container App alongside your workshop infra:

module proxy 'modules/proxy.bicep' = {
  name: 'proxy'
  params: {
    name: 'idp-proxy'
    environmentId: appEnv.outputs.environmentId
    userAssignedIdentityId: identity.id
    ptuEndpoint: 'https://my-ptu.openai.azure.com'
    paygEndpoint: 'https://my-payg.openai.azure.com'
  }
}

SimpleL7Proxy configuration via environment variables:

# Backend endpoints (mode=direct for Azure AI Services)
Host1="host=https://my-ptu.openai.azure.com;usemi=true;mode=direct"
Host2="host=https://my-payg.openai.azure.com;usemi=true;mode=direct"

# Routing — latency-based prefers the faster (non-throttled) endpoint
LoadBalanceMode=latency
IterationMode=MultiPass

# Circuit breaker — failover after 20 errors in 60s
CBErrorThreshold=20
CBTimeslice=60

# Workers and queue
Workers=50
MaxQueueLength=500

🔧 Behind the Scenes — How This Works

Azure Resources Required

  • AI Services (Foundry) — GPT-4.1 + text-embedding-3-large deployments for CU
  • AI Search (Basic+) — semantic search with reranking
  • SimpleL7Proxy (Container App) — routes between PTU and PAYG endpoints
  • Managed Identity — RBAC for all services, no API keys

Batch Pipeline Flow

  1. Ensure AI Search index exists (create if needed)
  2. For each document: read sample → CU enrichment (summary + key_topics) → build search document → push to index
  3. Return per-document results with timing and API traces

Production Scaling

This workshop demo processes documents sequentially. In production, you'd add: Azure Storage Queue for document intake, parallel workers pulling from the queue, SimpleL7Proxy routing CU calls through PTU capacity, and dead-letter handling for failures.
