💡 What to Notice — DI Falls Short Here

        
    
            
  • DI is text/layout extraction. CU is document understanding. That's the fundamental difference.
    • 
            
  • DI gave you a wall of text. CU gave you structured, actionable intelligence — parties, obligations, risk.
    • 
            
  • For unstructured documents (contracts, emails, reports), DI simply can't answer "who are the parties?" or "what's the risk?"
    • 
            
  • This is why CU exists — to bridge the gap from reading documents to understanding them.
    • 
            
  • Next: Module 3 shows how you define your own custom fields for any document type.

☁️ Azure Resources Required

                    
    
                        
  • Azure AI Services (kind: AIServices)
    • 
                        
  • GPT-4.1 model deployment — CU uses this for GenAI inference
    • 
                        
  • DI only needs the base AI Services resource
    • 
                        
  • Managed Identity for auth (no API keys)
    • 
                    

                

                

                    
🔗 REST API Endpoints

                    

                        
DI Layout: POST /formrecognizer/documentModels/prebuilt-layout:analyze

                        
CU Custom: POST /contentunderstanding/analyzers/{id}:analyze

                    

                    
DI uses a generic layout model. CU uses a custom analyzer with your field definitions + GenAI.
