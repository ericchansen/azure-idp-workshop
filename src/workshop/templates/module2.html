Module 2: Semantic Extraction & Custom Fields

CU's custom field inference uses GenAI to extract summaries, entities, sentiment, and risk from any document — define your own fields and watch CU understand documents, not just read them. We also run DI side-by-side so you can see the difference: DI extracts text but can't infer meaning.

CU custom analyzer is created once with a field schema, then reused for each document. GPT-4.1 powers the GenAI inference step that extracts your custom fields. DI uses a generic layout model — no semantic understanding.

🔬 What Are We Comparing?

🔵 Document Intelligence (DI)

DI's layout model extracts raw text and structure. On unstructured documents like contracts, it gives you a wall of text — no semantic understanding, no summaries, no risk assessment.

🟣 Content Understanding (CU)

CU creates a custom analyzer with YOUR field definitions. It uses GPT-4.1 to understand the document and infer each field — summaries, entities, sentiment, risk. No training data needed.

🏭 When to Use This in Production

  • Contract analysis and review — extract parties, obligations, and risk from legal agreements
  • Ad-hoc document analysis — define fields without training a model
  • Insurance claim processing — understand claim narratives and extract key facts automatically
  • Compliance review — infer sentiment, flag issues, categorize documents
  • Research paper analysis — extract methodology, findings, citations
  • Any document where you need to extract meaning, not just text

🔬 Try It Yourself

# pip install azure-ai-documentintelligence azure-ai-contentunderstanding azure-identity
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.identity import DefaultAzureCredential

endpoint = "https://<your-resource>.cognitiveservices.azure.com"
credential = DefaultAzureCredential()
client = ContentUnderstandingClient(endpoint, credential)

# Create a custom analyzer (one-time setup)
analyzer_def = {
    "description": "Contract analyzer",
    "scenario": "document",
    "fieldSchema": {
        "fields": {
            "summary": {"type": "string", "description": "2-3 sentence summary"},
            "key_parties": {"type": "string", "description": "Names of all parties"},
            "obligations": {"type": "string", "description": "Key obligations"},
            "risk_level": {"type": "string", "description": "Risk: low/medium/high"},
            "sentiment": {"type": "string", "description": "Sentiment: positive/neutral/negative"},
        }
    },
    "config": {
        "baseAnalyzerId": "prebuilt-document",
        "models": {"completion": "gpt-4.1"}
    }
}
client.begin_create_analyzer("contract-analyzer", body=analyzer_def).result()

# Analyze a contract
with open("contract.pdf", "rb") as f:
    poller = client.begin_analyze("contract-analyzer", body=f.read(), content_type="application/octet-stream")
result = poller.result()
for content in result["contents"]:
    print(f"Summary: {content['fields']['summary']['valueString']}")
    print(f"Risk: {content['fields']['risk_level']['valueString']}")
# Get an access token (requires az login)
TOKEN=$(az account get-access-token --resource https://cognitiveservices.azure.com --query accessToken -o tsv)
ENDPOINT="https://<your-resource>.cognitiveservices.azure.com"

# --- Step 1: Create a custom analyzer (one-time) ---
curl -X PUT "$ENDPOINT/contentunderstanding/analyzers/contract-analyzer?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Contract analyzer",
    "scenario": "document",
    "fieldSchema": {
      "fields": {
        "summary": {"type": "string", "description": "2-3 sentence summary"},
        "key_parties": {"type": "string", "description": "Names of all parties"},
        "obligations": {"type": "string", "description": "Key obligations"},
        "risk_level": {"type": "string", "description": "Risk: low/medium/high"},
        "sentiment": {"type": "string", "description": "Sentiment: positive/neutral/negative"}
      }
    },
    "config": {"baseAnalyzerId": "prebuilt-document", "models": {"completion": "gpt-4.1"}}
  }'

# --- Step 2: Analyze a contract ---
CU_URL=$(curl -s -D - -X POST "$ENDPOINT/contentunderstanding/analyzers/contract-analyzer:analyze?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/pdf" \
  --data-binary @contract.pdf | grep -i operation-location | tr -d '\r' | cut -d' ' -f2)
# Poll for result
curl -s -H "Authorization: Bearer $TOKEN" "$CU_URL" | python -m json.tool

🧱 Infrastructure as Code

CU custom analyzers require BOTH GPT-4.1 and text-embedding-3-large model deployments:

resource aiServices 'Microsoft.CognitiveServices/accounts@2024-10-01' = {
  name: 'my-ai-services'
  location: 'eastus'
  kind: 'AIServices'
  sku: { name: 'S0' }
  properties: {
    customSubDomainName: 'my-ai-services'
    publicNetworkAccess: 'Enabled'
  }
}

// GPT-4.1 — powers CU's GenAI field inference
resource gpt41 'Microsoft.CognitiveServices/accounts/deployments@2024-10-01' = {
  parent: aiServices
  name: 'gpt-4.1'
  sku: { name: 'GlobalStandard', capacity: 10 }
  properties: {
    model: { format: 'OpenAI', name: 'gpt-4.1', version: '2025-04-14' }
  }
}

// Text embedding — required for CU's semantic understanding
resource embedding 'Microsoft.CognitiveServices/accounts/deployments@2024-10-01' = {
  parent: aiServices
  name: 'text-embedding-3-large'
  dependsOn: [gpt41]
  sku: { name: 'Standard', capacity: 10 }
  properties: { model: { format: 'OpenAI', name: 'text-embedding-3-large', version: '1' } }
}

    capacity = 10

  model {
    format  = "OpenAI"
    name    = "text-embedding-3-large"
    version = "1"
  }

🔍 Side-by-Side Comparison Guide

🧠 GenAI vs Deterministic

CU uses GPT-4.1 to infer fields — results may vary slightly between runs. DI is deterministic: same input, same output. CU delivers understanding; DI delivers text.

📋 Schema-Driven, No Training

You defined 5 fields. CU extracted all 5 using GenAI — no labeled training data needed. Traditional ML extraction requires thousands of labeled examples.

💰 Cost vs Value

CU costs 5× more ($0.05 vs $0.01/page) — but it delivers structured intelligence, not a wall of text. Check the API trace for token usage.

💡 What to Notice — CU's Semantic Superpower

  • DI is text/layout extraction. CU is document understanding. That's the fundamental difference.
  • DI gave you a wall of text. CU gave you structured, actionable intelligence — parties, obligations, sentiment, risk.
  • The custom fields were defined by YOU — try adding your own! CU uses GenAI to infer them. No model training, no labeled datasets.
  • Description quality matters. Better field descriptions → more accurate extraction. Click to edit and experiment.
  • DI cannot do this at all — it has no concept of "summarize" or "assess risk." That's why CU exists.
  • CU's custom fields use your Foundry model deployment (GPT-4.1) — check the API trace for token usage and cost.
📚 Behind the Scenes — How This Works

☁️ Azure Resources Required

  • Azure AI Services (kind: AIServices)
  • GPT-4.1 model deployment — CU uses this for GenAI inference
  • text-embedding-3-large — for semantic understanding
  • Custom analyzers are created via API with a fieldSchema
  • Managed Identity for auth (no API keys)

🔗 REST API Flow

1. PUT /contentunderstanding/analyzers/{id} (create once)
2. POST /contentunderstanding/analyzers/{id}:analyze
3. GET /contentunderstanding/analyzers/{id}/results/{rid}
DI: POST /formrecognizer/documentModels/prebuilt-layout:analyze

Analyzers are created once and reused. Fields are defined in the fieldSchema.

💰 Pricing Comparison

DI Layout: $0.01/page (text only)
CU Custom: $0.05/page (includes GenAI)

CU Custom costs 5× more — but it delivers understanding, not just text. The right tool depends on what you need.
