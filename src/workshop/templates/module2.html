Module 2: Unstructured Documents — When DI Falls Short

DI extracts text. CU infers meaning. See the difference on contracts and unstructured documents — DI gives you layout, CU gives you understanding.

DI uses a generic layout model. CU uses a custom analyzer that feeds the document through GPT-4.1 for semantic inference — extracting meaning, not just text.

🔬 What Are We Comparing?

🔵 Document Intelligence (DI)

DI's layout model extracts raw text and structure. On unstructured documents like contracts, it gives you a wall of text with no semantic understanding.

🟣 Content Understanding (CU)

CU's custom analyzer uses GPT-4.1 to understand the document. It infers structured fields like summaries, key parties, obligations, and risk — things DI simply can't do.

🏭 When to Use This in Production

  • Contract analysis and review — extract parties, obligations, and risk from legal agreements
  • Insurance claim processing — understand claim narratives and extract key facts automatically
  • Legal document understanding — summarize briefs, identify clauses, and flag risks
  • Medical record summarization — extract diagnoses, treatments, and key findings from clinical notes
  • Any document where you need to extract meaning, not just text

🔬 Try It Yourself

# pip install azure-ai-documentintelligence azure-ai-contentunderstanding azure-identity
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.identity import DefaultAzureCredential

endpoint = "https://<your-resource>.cognitiveservices.azure.com"
credential = DefaultAzureCredential()
client = ContentUnderstandingClient(endpoint, credential)

# Create a custom analyzer (one-time setup)
analyzer_def = {
    "description": "Contract analyzer",
    "scenario": "document",
    "fieldSchema": {
        "fields": {
            "summary": {"type": "string", "description": "2-3 sentence summary"},
            "key_parties": {"type": "string", "description": "Names of all parties"},
            "obligations": {"type": "string", "description": "Key obligations"},
            "risk_level": {"type": "string", "description": "Risk: low/medium/high"},
        }
    },
    "config": {
        "baseAnalyzerId": "prebuilt-document",
        "models": {"completion": "gpt-4.1"}
    }
}
client.begin_create_analyzer("contract-analyzer", body=analyzer_def).result()

# Analyze a contract
with open("contract.pdf", "rb") as f:
    poller = client.begin_analyze("contract-analyzer", body=f.read(), content_type="application/octet-stream")
result = poller.result()
for content in result["contents"]:
    print(f"Summary: {content['fields']['summary']['valueString']}")
    print(f"Risk: {content['fields']['risk_level']['valueString']}")
# Get an access token (requires az login)
TOKEN=$(az account get-access-token --resource https://cognitiveservices.azure.com --query accessToken -o tsv)
ENDPOINT="https://<your-resource>.cognitiveservices.azure.com"

# --- Step 1: Create a custom analyzer (one-time) ---
curl -X PUT "$ENDPOINT/contentunderstanding/analyzers/contract-analyzer?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Contract analyzer",
    "scenario": "document",
    "fieldSchema": {
      "fields": {
        "summary": {"type": "string", "description": "2-3 sentence summary"},
        "key_parties": {"type": "string", "description": "Names of all parties"},
        "obligations": {"type": "string", "description": "Key obligations"},
        "risk_level": {"type": "string", "description": "Risk: low/medium/high"}
      }
    },
    "config": {"baseAnalyzerId": "prebuilt-document", "models": {"completion": "gpt-4.1"}}
  }'

# --- Step 2: Analyze a contract ---
CU_URL=$(curl -s -D - -X POST "$ENDPOINT/contentunderstanding/analyzers/contract-analyzer:analyze?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/pdf" \
  --data-binary @contract.pdf | grep -i operation-location | tr -d '\r' | cut -d' ' -f2)
# Poll for result
curl -s -H "Authorization: Bearer $TOKEN" "$CU_URL" | python -m json.tool

    format  = "OpenAI"
    name    = "gpt-4.1"

  }
}

🔍 Side-by-Side Comparison Guide

🧠 Understanding vs Text

DI gave you text. CU gave you meaning. Can DI tell you who the parties are? No. CU extracts structured intelligence that DI simply cannot.

💰 Cost vs Value

CU costs 5× more ($0.05 vs $0.01/page) — but it delivers structured intelligence, not a wall of text. The ROI depends on whether you need understanding or just OCR.

⏱️ Speed Trade-off

CU is slower because of GenAI inference. For batch processing, consider if you need understanding or just text. DI is better for high-volume text extraction.

💡 What to Notice — DI Falls Short Here

  • DI is text/layout extraction. CU is document understanding. That's the fundamental difference.
  • DI gave you a wall of text. CU gave you structured, actionable intelligence — parties, obligations, risk.
  • For unstructured documents (contracts, emails, reports), DI simply can't answer "who are the parties?" or "what's the risk?"
  • This is why CU exists — to bridge the gap from reading documents to understanding them.

  • DI only needs the base AI Services resource

🔗 REST API Endpoints

CU Custom: POST /contentunderstanding/analyzers/{id}:analyze
