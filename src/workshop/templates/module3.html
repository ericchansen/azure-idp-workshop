Module 3: Document Search with AI

Use CU to enrich documents, push to Azure AI Search, then query with semantic ranking.

🏗️ Architecture & Setup

📐 Data Flow

📄 Document → 🟣 CU Extraction → 🔎 AI Search Index → ✅ Semantic Query
CU enriches the document with summaries and key topics → pushed to AI Search → queryable with semantic ranking

📥 Push vs Pull Indexing

⬆️ Push Model (This Demo)
  • Your app sends documents to the index via the SDK
  • Full control over enrichment pipeline
  • CU/DI pre-processes before indexing
  • Best for: custom enrichment, event-driven ingestion
⬇️ Pull Model (Indexers)
  • AI Search crawls a data source (Blob, SQL, Cosmos DB)
  • Built-in skillsets for enrichment
  • Scheduled or on-demand
  • Best for: bulk ingestion, blob storage pipelines

🎯 What We're Building

A CU-powered document knowledge base. This module shows the complete pipeline:

  1. Select a document from the sample library
  2. CU extracts a summary and key topics (GenAI enrichment)
  3. The enriched document is pushed to Azure AI Search
  4. You can then search across indexed documents with semantic ranking

🧑‍💻 Try It Yourself

from azure.search.documents import SearchClient
from azure.search.documents.indexes import SearchIndexClient
from azure.identity import DefaultAzureCredential

credential = DefaultAzureCredential()

# Create index
index_client = SearchIndexClient(endpoint, credential)
index_client.create_or_update_index(index)

# Push document
search_client = SearchClient(endpoint, "documents", credential)
search_client.upload_documents([{
    "id": "doc-1",
    "title": "Contract.pdf",
    "content": "Full document text...",
    "summary": "Professional services agreement...",
}])

# Search
results = search_client.search(
    search_text="service agreement",
    query_type="semantic",
    semantic_configuration_name="default",
)
for r in results:
    print(f"{r['title']}: {r['@search.score']}")
# Index a document
curl -X POST "https://<search-service>.search.windows.net/indexes/documents/docs/index?api-version=2024-07-01" \
  -H "api-key: <key>" \
  -H "Content-Type: application/json" \
  -d '{"value": [{"@search.action": "upload", "id": "doc-1", "title": "Contract.pdf", "content": "..."}]}'

# Search
curl "https://<search-service>.search.windows.net/indexes/documents/docs/search?api-version=2024-07-01" \
  -H "api-key: <key>" \
  -H "Content-Type: application/json" \
  -d '{"search": "service agreement", "queryType": "semantic", "semanticConfiguration": "default"}'

🎯 What to Look For

  • CU enrichment — CU extracts a summary and key topics before indexing. This is the "1+1=3" story.
  • Two API calls — First CU analyzes, then AI Search indexes. Check both traces.
  • Processing time — CU inference dominates; the search indexing is near-instant.

🔍 Step 2: Search Your Knowledge Base

Query the index with natural language. AI Search uses semantic ranking to find the most relevant documents.

💡 What to Notice — CU Makes Search Smarter

  • CU enrichment is the secret sauce. Without it, you're searching raw text. With it, you're searching structured intelligence.
  • Semantic ranking uses deep learning to understand query intent — "service obligations" matches even if the exact words aren't in the document.
  • Two-step pipeline: CU extraction (slow, GenAI) → Search indexing (fast, instant). In production, you'd run CU once and query many times.
  • Push model gives you full control. You decide what to enrich, when to index, and what metadata to attach.

🔑 RBAC vs. API Keys

Azure AI Search supports two authentication modes. RBAC is strongly recommended for production.

✅ RBAC (Recommended)
  • No secrets to manage, rotate, or leak
  • Granular per-identity permissions
  • Audit trail via Entra ID logs
  • Search Index Data Contributor — read/write index data
  • Search Service Contributor — manage index schema
⚠️ API Keys (Legacy)
  • Shared secret — anyone with the key gets full access
  • No per-user audit trail
  • Key rotation requires app redeployment
  • Admin key = full control (dangerous if leaked)
  • Query key = read-only (still a shared secret)

💡 Disable API key auth entirely with disableLocalAuth: true in your Bicep/Terraform.

🪪 Managed Identity

Managed identities eliminate the need for credentials in code or config. Azure handles token issuance and rotation.

System-Assigned
  • One identity per resource (1:1)
  • Lifecycle tied to the resource
  • Simpler — good for single-purpose apps
  • Used by this workshop's Container App
User-Assigned
  • Shared across multiple resources (1:N)
  • Independent lifecycle — survives redeployments
  • Better for microservices sharing the same permissions
  • Pre-create and assign RBAC before app deployment

🌐 Network Isolation

In production, AI Search should never be exposed to the public internet. Use private endpoints to restrict access to your VNet.

Container App
→
Private Endpoint
→
AI Search (no public IP)
  • Private endpoint: Creates a NIC in your VNet with a private IP for the search service
  • DNS integration: Use Azure Private DNS Zone (privatelink.search.windows.net) for name resolution
  • Public access: Set publicNetworkAccess: 'Disabled' after private endpoint is active
  • VNet integration: Container Apps Environment must be injected into the same VNet (or peered)

🛡️ Data Exfiltration Protection

Prevent indexed data from being copied to unauthorized destinations.

  • Private Link scoping: Limit which resources can access the search service via approved private endpoints
  • NSG rules: Restrict outbound traffic from application subnets and the private endpoint subnet to only required Azure AI Search endpoints
  • Azure Policy: Enforce privateEndpointConnections and deny public network access at the subscription level
  • Managed Identity restrictions: Grant only the minimum RBAC roles needed (avoid Owner/Contributor on the search resource)

🔒 Encryption at Rest

All data in Azure AI Search is encrypted at rest by default. For compliance-sensitive workloads, use customer-managed keys.

Service-Managed (Default)
  • Microsoft manages encryption keys
  • AES-256 encryption
  • Zero configuration — always on
  • Sufficient for most workloads
Customer-Managed Keys (CMK)
  • You control the key in Azure Key Vault
  • Required for some compliance standards (FedRAMP High, HIPAA)
  • Enables "double encryption" — your key + Microsoft's
  • Key rotation without re-indexing

🏗️ Secure Deployment — Infrastructure as Code

Production-ready IaC that combines RBAC, private endpoints, disabled API keys, and diagnostic logging.

// AI Search — RBAC-only, no public access, diagnostic logging
resource searchService 'Microsoft.Search/searchServices@2024-06-01-preview' = {
  name: searchServiceName
  location: location
  sku: { name: 'basic' }
  identity: { type: 'SystemAssigned' }
  properties: {
    publicNetworkAccess: 'Disabled'
    disableLocalAuth: true          // No API keys
    semanticSearch: 'standard'
    authOptions: {
      aadOrApiKey: { aadAuthFailureMode: 'http401WithBearerChallenge' }
    }
  }
}

// Private endpoint for AI Search
resource searchPe 'Microsoft.Network/privateEndpoints@2023-11-01' = {
  name: '${searchServiceName}-pe'
  location: location
  properties: {
    subnet: { id: subnetId }
    privateLinkServiceConnections: [{
      name: '${searchServiceName}-plsc'
      properties: {
        privateLinkServiceId: searchService.id
        groupIds: [ 'searchService' ]
      }
    }]
  }
}

// Private DNS zone for private endpoint name resolution
resource searchDnsZone 'Microsoft.Network/privateDnsZones@2020-06-01' = {
  name: 'privatelink.search.windows.net'
  location: 'global'
}

resource searchDnsZoneLink 'Microsoft.Network/privateDnsZones/virtualNetworkLinks@2020-06-01' = {
  parent: searchDnsZone
  name: '${searchServiceName}-dns-link'
  location: 'global'
  properties: {
    virtualNetwork: { id: virtualNetworkId }
    registrationEnabled: false
  }
}

resource searchDnsZoneGroup 'Microsoft.Network/privateEndpoints/privateDnsZoneGroups@2023-11-01' = {
  parent: searchPe
  name: 'search-dns-zone-group'
  properties: {
    privateDnsZoneConfigs: [{
      name: 'search-dns-config'
      properties: { privateDnsZoneId: searchDnsZone.id }
    }]
  }
}

// RBAC: Grant the Container App access to search data
resource searchDataContributor 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  scope: searchService
  name: guid(searchService.id, containerApp.id, searchIndexDataContributorId)
  properties: {
    roleDefinitionId: subscriptionResourceId(
      'Microsoft.Authorization/roleDefinitions',
      '8ebe5a00-799e-43f5-93ac-243d3dce84a7' // Search Index Data Contributor
    )
    principalId: containerApp.identity.principalId
    principalType: 'ServicePrincipal'
  }
}

// RBAC: Grant the Container App permissions to manage index schemas
resource searchServiceContributor 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  scope: searchService
  name: guid(searchService.id, containerApp.id, 'search-service-contributor')
  properties: {
    roleDefinitionId: subscriptionResourceId(
      'Microsoft.Authorization/roleDefinitions',
      '7ca78c08-252a-4474-88e0-6f84bd1e5c58' // Search Service Contributor
    )
    principalId: containerApp.identity.principalId
    principalType: 'ServicePrincipal'
  }
}

// Diagnostic logging to Log Analytics
resource searchDiag 'Microsoft.Insights/diagnosticSettings@2021-05-01-preview' = {
  name: 'search-diagnostics'
  scope: searchService
  properties: {
    workspaceId: logAnalyticsWorkspace.id
    logs: [
      { categoryGroup: 'allLogs', enabled: true }
    ]
    metrics: [
      { category: 'AllMetrics', enabled: true }
    ]
  }
}
# AI Search — RBAC-only, no public access
resource "azurerm_search_service" "search" {
  name                          = var.search_service_name
  resource_group_name           = azurerm_resource_group.rg.name
  location                      = azurerm_resource_group.rg.location
  sku                           = "basic"
  semantic_search_sku           = "standard"
  public_network_access_enabled = false
  local_authentication_enabled  = false  # No API keys

  identity {
    type = "SystemAssigned"
  }
}

# Private endpoint for AI Search
resource "azurerm_private_endpoint" "search_pe" {
  name                = "${var.search_service_name}-pe"
  location            = azurerm_resource_group.rg.location
  resource_group_name = azurerm_resource_group.rg.name
  subnet_id           = azurerm_subnet.private.id

  private_service_connection {
    name                           = "${var.search_service_name}-plsc"
    private_connection_resource_id = azurerm_search_service.search.id
    subresource_names              = ["searchService"]
    is_manual_connection           = false
  }

  private_dns_zone_group {
    name                 = "search-dns"
    private_dns_zone_ids = [azurerm_private_dns_zone.search.id]
  }
}

# Private DNS zone for search
resource "azurerm_private_dns_zone" "search" {
  name                = "privatelink.search.windows.net"
  resource_group_name = azurerm_resource_group.rg.name
}

# RBAC: Search Index Data Contributor
resource "azurerm_role_assignment" "search_data" {
  scope                = azurerm_search_service.search.id
  role_definition_name = "Search Index Data Contributor"
  principal_id         = azurerm_container_app.app.identity[0].principal_id
}

# RBAC: Search Service Contributor (index schema management)
resource "azurerm_role_assignment" "search_service" {
  scope                = azurerm_search_service.search.id
  role_definition_name = "Search Service Contributor"
  principal_id         = azurerm_container_app.app.identity[0].principal_id
}

# Diagnostic logging
resource "azurerm_monitor_diagnostic_setting" "search_diag" {
  name                       = "search-diagnostics"
  target_resource_id         = azurerm_search_service.search.id
  log_analytics_workspace_id = azurerm_log_analytics_workspace.logs.id

  enabled_log { category_group = "allLogs" }
  metric      { category = "AllMetrics" }
}
