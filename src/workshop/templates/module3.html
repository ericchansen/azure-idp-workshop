Module 3: Document Search with AI

Use CU to enrich documents, push to Azure AI Search, then query with semantic ranking.

🏗️ Architecture & Setup

📐 Data Flow

📄 Document → 🟣 CU Extraction → 🔎 AI Search Index → ✅ Semantic Query
CU enriches the document with summaries and key topics → pushed to AI Search → queryable with semantic ranking

📥 Push vs Pull Indexing

⬆️ Push Model (This Demo)
  • Your app sends documents to the index via the SDK
  • Full control over enrichment pipeline
  • CU/DI pre-processes before indexing
  • Best for: custom enrichment, event-driven ingestion
⬇️ Pull Model (Indexers)
  • AI Search crawls a data source (Blob, SQL, Cosmos DB)
  • Built-in skillsets for enrichment
  • Scheduled or on-demand
  • Best for: bulk ingestion, blob storage pipelines

🎯 What We're Building

A CU-powered document knowledge base. This module shows the complete pipeline:

  1. Select a document from the sample library
  2. CU extracts a summary and key topics (GenAI enrichment)
  3. The enriched document is pushed to Azure AI Search
  4. You can then search across indexed documents with semantic ranking

🧑‍💻 Try It Yourself

from azure.search.documents import SearchClient
from azure.search.documents.indexes import SearchIndexClient
from azure.identity import DefaultAzureCredential

credential = DefaultAzureCredential()

# Create index
index_client = SearchIndexClient(endpoint, credential)
index_client.create_or_update_index(index)

# Push document
search_client = SearchClient(endpoint, "documents", credential)
search_client.upload_documents([{
    "id": "doc-1",
    "title": "Contract.pdf",
    "content": "Full document text...",
    "summary": "Professional services agreement...",
}])

# Search
results = search_client.search(
    search_text="service agreement",
    query_type="semantic",
    semantic_configuration_name="default",
)
for r in results:
    print(f"{r['title']}: {r['@search.score']}")
# Index a document
curl -X POST "https://<search-service>.search.windows.net/indexes/documents/docs/index?api-version=2024-07-01" \
  -H "api-key: <key>" \
  -H "Content-Type: application/json" \
  -d '{"value": [{"@search.action": "upload", "id": "doc-1", "title": "Contract.pdf", "content": "..."}]}'

# Search
curl "https://<search-service>.search.windows.net/indexes/documents/docs/search?api-version=2024-07-01" \
  -H "api-key: <key>" \
  -H "Content-Type: application/json" \
  -d '{"search": "service agreement", "queryType": "semantic", "semanticConfiguration": "default"}'

📥 Step 1: Index a Document

Select a document. CU will extract a summary and key topics, then push the enriched document to Azure AI Search.

📊 Index: document(s)

🎯 What to Look For

  • CU enrichment — CU extracts a summary and key topics before indexing. This is the "1+1=3" story.
  • Two API calls — First CU analyzes, then AI Search indexes. Check both traces.
  • Processing time — CU inference dominates; the search indexing is near-instant.

🔍 Step 2: Search Your Knowledge Base

Query the index with natural language. AI Search uses semantic ranking to find the most relevant documents.

💡 What to Notice — CU Makes Search Smarter

  • CU enrichment is the secret sauce. Without it, you're searching raw text. With it, you're searching structured intelligence.
  • Semantic ranking uses deep learning to understand query intent — "service obligations" matches even if the exact words aren't in the document.
  • Two-step pipeline: CU extraction (slow, GenAI) → Search indexing (fast, instant). In production, you'd run CU once and query many times.
  • Push model gives you full control. You decide what to enrich, when to index, and what metadata to attach.
📚 Behind the Scenes — How This Works

☁️ Azure Resources Required

  • Azure AI Search (Basic SKU) — semantic ranking enabled
  • Azure AI Services — CU for document enrichment
  • GPT-4.1 deployment — CU uses this for field extraction
  • Managed Identity for auth (no API keys)

🔐 Security Patterns

  • Managed Identity — no keys in code or config
  • RBAC roles: Search Index Data Contributor + Search Service Contributor
  • Network isolation: Private endpoints + VNet integration in production
  • Data encryption at rest (service-managed keys)
