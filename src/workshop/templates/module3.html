CU custom analyzer is created once with a field schema, then reused for each document. GPT-4.1 powers the GenAI inference step that extracts your custom fields.

🔬 What Are We Comparing?

🟣 CU Custom Fields

CU creates a custom analyzer with YOUR field definitions. It uses GPT-4.1 to understand the document and infer each field — summaries, entities, sentiment, risk. No training data needed.

🔵 DI Layout (Baseline)

DI can only extract text and layout. It has no concept of "summarize this" or "assess risk". Shown here as a baseline to demonstrate what CU adds.

🏭 When to Use This in Production

  • Ad-hoc document analysis — define fields without training a model
  • Contract intelligence — extract parties, obligations, deadlines, risk
  • Compliance review — infer sentiment, flag issues, categorize documents
  • Research paper analysis — extract methodology, findings, citations
  • Any scenario where you need structured data from unstructured documents

🔬 Try It Yourself

# pip install azure-ai-contentunderstanding azure-identity
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.identity import DefaultAzureCredential

endpoint = "https://<your-resource>.cognitiveservices.azure.com"
client = ContentUnderstandingClient(endpoint, DefaultAzureCredential())

# Step 1: Define custom fields (your schema)
analyzer_def = {
    "description": "Contract analyzer with sentiment",
    "scenario": "document",
    "fieldSchema": {
        "fields": {
            "summary": {"type": "string", "description": "2-3 sentence summary"},
            "key_parties": {"type": "string", "description": "Names of all parties"},
            "obligations": {"type": "string", "description": "Key obligations"},
            "risk_level": {"type": "string", "description": "Risk: low/medium/high"},
            "sentiment": {"type": "string", "description": "Sentiment: positive/neutral/negative"},
        }
    },
    "config": {
        "baseAnalyzerId": "prebuilt-document",
        "models": {"completion": "gpt-4.1"}
    }
}

# Step 2: Create the analyzer (one-time, reusable)
client.begin_create_analyzer("my-analyzer", body=analyzer_def, allow_replace=True).result()

# Step 3: Analyze any document
with open("contract.pdf", "rb") as f:
    poller = client.begin_analyze("my-analyzer", body=f.read(), content_type="application/octet-stream")
result = poller.result()

# Step 4: Access inferred fields
for content in result["contents"]:
    for field_name, field_data in content["fields"].items():
        print(f"{field_name}: {field_data.get('valueString', 'N/A')}")
# Get an access token (requires az login)
TOKEN=$(az account get-access-token --resource https://cognitiveservices.azure.com --query accessToken -o tsv)
ENDPOINT="https://<your-resource>.cognitiveservices.azure.com"

# --- Step 1: Create a Custom Analyzer with field schema ---
curl -X PUT "$ENDPOINT/contentunderstanding/analyzers/my-contract?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Contract analyzer with sentiment",
    "scenario": "document",
    "fieldSchema": {
      "fields": {
        "summary": {"type": "string", "description": "2-3 sentence summary"},
        "key_parties": {"type": "string", "description": "Names of all parties"},
        "obligations": {"type": "string", "description": "Key obligations"},
        "risk_level": {"type": "string", "description": "Risk: low/medium/high"},
        "sentiment": {"type": "string", "description": "Sentiment: positive/neutral/negative"}
      }
    },
    "config": {
      "baseAnalyzerId": "prebuilt-document",
      "models": {"completion": "gpt-4.1"}
    }
  }'

# --- Step 2: Analyze a document with the custom analyzer ---
CU_URL=$(curl -s -D - -X POST "$ENDPOINT/contentunderstanding/analyzers/my-contract:analyze?api-version=2025-05-01-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/pdf" \
  --data-binary @contract.pdf | grep -i operation-location | tr -d '\r' | cut -d' ' -f2)

# --- Step 3: Poll for result ---
curl -s -H "Authorization: Bearer $TOKEN" "$CU_URL" | python -m json.tool

🧱 Infrastructure as Code

CU custom analyzers require BOTH GPT-4.1 and text-embedding-3-large model deployments:

resource aiServices 'Microsoft.CognitiveServices/accounts@2024-10-01' = {
  name: 'my-ai-services'
  location: 'eastus'
  kind: 'AIServices'
  sku: { name: 'S0' }
  properties: { customSubDomainName: 'my-ai-services' }
}

// GPT-4.1 — powers CU's GenAI field inference
resource gpt41 'Microsoft.CognitiveServices/accounts/deployments@2024-10-01' = {
  parent: aiServices
  name: 'gpt-41'
  sku: { name: 'GlobalStandard', capacity: 10 }
  properties: { model: { format: 'OpenAI', name: 'gpt-4.1', version: '2025-04-14' } }
}

// Text embedding — required for CU's semantic understanding
resource embedding 'Microsoft.CognitiveServices/accounts/deployments@2024-10-01' = {
  parent: aiServices
  name: 'text-embedding-3-large'
  dependsOn: [gpt41]
  sku: { name: 'Standard', capacity: 10 }
  properties: { model: { format: 'OpenAI', name: 'text-embedding-3-large', version: '1' } }
}

🔍 Side-by-Side Comparison Guide

🧠 GenAI vs Deterministic

CU uses GPT-4.1 to infer fields. Results may vary slightly between runs. DI is deterministic — same input always gives same output.

📋 Schema-Driven

You defined 5 fields. CU extracted all 5. Try changing the field descriptions and re-running — CU adapts instantly, no retraining.

💡 No Training Data

Traditional ML document extraction requires labeled training data. CU needs zero — just a description of what you want.

💡 What to Notice — CU's Superpower

  • This is CU's superpower: GenAI-powered semantic extraction on any document type. No predefined fields or training needed.
  • CU understands the document — it produces summaries, identifies parties, and assesses risk. DI just gives you the raw text.
  • The custom fields were defined by YOU — CU used GenAI to infer them. No model training, no labeled datasets.
  • DI cannot do this at all — it has no concept of "summarize" or "assess risk." That's the fundamental difference.
  • CU's custom fields use your Foundry model deployment (GPT-4.1) — check the API trace for token usage and cost.
📚 Behind the Scenes — How This Works

☁️ Azure Resources Required

  • Azure AI Services (kind: AIServices)
  • GPT-4.1 model deployment — CU uses this for GenAI inference
  • text-embedding-3-large — for semantic understanding
  • Custom analyzers are created via API with a fieldSchema

🔗 REST API Flow

1. PUT /contentunderstanding/analyzers/{id} (create)
2. POST /contentunderstanding/analyzers/{id}:analyze
3. GET /contentunderstanding/analyzers/{id}/results/{rid}

Analyzers are created once and reused. Fields are defined in the fieldSchema.
